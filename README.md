# 사이 SAI — 커플 스마트링 HTML 목업

20–30대 한국·일본 커플을 위한 스마트링 + 앱 + 분석 구독 콘셉트입니다. 서버 설치나 실행 없이 HTML 파일을 브라우저에서 엽니다.

## 최신 목업 열기

**`pair.html` 또는 `mobile.html`을 더블클릭하세요. 두 파일은 같은 최신 버전입니다.**

- PC: 수민과 지우의 휴대폰 화면이 나란히 표시됩니다. 각각 따로 스크롤하고 조작합니다.
- 좁은 화면·휴대폰: 상단 ‘수민의 화면 / 지우의 화면’으로 전환합니다. 상대에게 새 반응이 오면 개수가 표시됩니다.
- 각 화면에서 자신의 선택을 입력하면 상대 화면에도 반영됩니다. 한 사람이 양쪽의 참여를 자동으로 승인하지 않습니다.
- HTML에 스타일과 코드를 모두 포함했습니다. **파일 하나만 전달해도 작동**합니다. 외부 폰트·이미지·패키지·서버가 필요 없습니다.
- 상단 KR / JP로 두 화면의 언어를 함께 바꿀 수 있습니다. 각 앱 안의 언어 선택은 그 화면에만 적용됩니다.
- 상단 ↺ 또는 PC 가운데 ‘체험 처음부터’로 이 목업의 기록을 초기화합니다.

## 바로 시연하는 순서

상단의 시연 바로가기는 두 화면을 해당 기능으로 이동시킵니다. 선택이나 참여는 자동으로 대신하지 않습니다.

| 바로가기 | 첫 번째 화면 | 상대 화면 | 결과 |
|---|---|---|---|
| 데이트 정하기 | 9월 12일에 데이트 모드 선택 | 같은 모드 선택 | 두 달력에 같은 약속 생성. 선택이 달라지면 이전 합의는 해제 |
| 배려 주고받기 | 필요한 배려 선택 | ‘내가 챙길게’ → ‘완료했어’ | 요청·수락·완료가 양쪽에 반영 |
| 심박 터치 | 예시 심박 선택 → 1건 공유 동의 → 보내기 | 도착한 리듬이 해당 속도로 맥동 → 수신 확인 | 보낸 사람에게도 수신 확인 표시 |
| 함께 호흡 | 동의하고 초대 | 동의하고 참여 | 같은 시작 시점의 24초 가이드. 둘의 달력에 완료 기록 |
| 같이 걷기 | 초대 후 자기 목표 선택·예시 걸음 추가 | 참여 후 자기 목표·예시 걸음 추가 | 각자의 목표를 모두 달성하면 공동 스탬프 |
| 데이트 기록 | 초대 후 순간 표시 | 참여 후 자신의 순간 표시 | 종료하면 시간·예시 수치·두 사람의 순간이 같은 추억 카드에 저장 |
| 수면 정원 | 수면 사용 동의 후 푹 잔 날 예시 적용 | 동일하게 자신의 수면 참여·예시 적용 | 둘이 완료한 날 꽃 한 송이 |
| 편한 시간 | 편한 시간 선택 | 자신의 편한 시간 선택 | 겹치는 시간 중 둘이 같은 시간을 고르면 통화 약속 생성 |

활동 초대 수신자는 알림 카드나 종 모양 버튼으로 해당 화면에 이동할 수 있습니다. 상대 화면의 현재 화면을 강제로 바꾸지 않습니다. 호흡·산책·데이트는 중간에 종료할 수 있으며 미완료 활동은 완료 보상을 남기지 않습니다.

## 리듬 캘린더

- 2026년 월간 달력, 월 이동, 날짜 선택, 날짜별 두 사람의 수면 요약
- 예시 오늘은 **2026년 9월 8일**로 고정
- 과거·오늘의 예시 기록은 채운 점, 미래의 미기록은 빈 점
- 생리 예상 기간은 점선 테두리와 ‘예상’ 표시. 측정값·개인 기록·예상을 구분
- 날짜별 데이트 선택, 돌봄 요청, 완료한 공동 활동과 추억 조회
- 생리 기록은 입력 시작일에서 27~31일 후를 예시 예상 기간으로 표시하는 단순 데모입니다. 실제 알고리즘·진단·피임 기능이 아닙니다.

## 각자의 정보와 공유

‘나의 사이’에서 **자기 정보만** 공유하거나 숨깁니다.

- 기분·한마디, 수면 요약: 초기 예시에서는 공유
- 안정 시 심박, 생리 예상 기간: 기본 비공개
- 몸 상태 메모: 항상 본인만 표시
- 수민이 주기 공유를 켜면 지우의 캘린더에도 예상 기간이 나타납니다. 끄면 바로 숨겨집니다.
- 주기를 공개하지 않고도 ‘따뜻한 음식’, ‘혼자 쉬는 시간’ 같은 필요한 배려만 요청할 수 있습니다.
- 심박 한 번 보내기와 공동 활동은 해당 활동에 별도로 동의합니다. 지속 공유 설정은 바뀌지 않습니다.
- 공유를 끄더라도 이미 동의하고 남긴 공동 활동·추억은 유지됩니다.

이것은 한 파일 안의 두 화면을 이용하는 UI 시연입니다. 표시 수준의 공유 제어이며, 실제 서비스의 서버 권한 제어를 구현한 것은 아닙니다.

## 기존 버전과 티저

- `mobile-single.html`: 이전의 휴대폰 한 화면 목업. 기존 기능은 그대로 보존
- `index.html`: 기존 PC 앱. 상단 ‘두 화면으로 함께 체험하기’로 최신 버전 이동
- 최신 티저: **`teaser.html`을 바로 엽니다.** 디자인과 동작이 내장되어 서버 없이 열립니다. 앱 체험 링크를 사용하려면 `pair.html`을 같은 폴더에 둡니다.
- 기존 `index.html#teaser` 진입점에서도 동일한 최신 티저를 볼 수 있습니다.
- 최신 두 화면 목업을 PC로 열면 상단 ‘티저 보기’ 링크 제공
- 기존 PC와 티저 전달 시 `index.html`, `style.css`, `app.js`를 같은 폴더에 둡니다.

티저에는 링 2개 세트 구매 + 커플 1쌍 월 구독 구조, 관심 기능·국가·예산 설문이 있습니다. 가격은 미정이며 예산 선택지는 지불 의향 조사입니다. 신청은 로컬 체험으로, 이메일을 저장·전송하지 않습니다.

## 데이터와 구현 한계

- 모든 링 연결·배터리·수면·심박·걸음은 예시입니다. 실제 링·Bluetooth·제조사 SDK에 연결하지 않습니다.
- 두 화면 사이의 반응은 부모 HTML의 공유 상태와 `postMessage`로 반영합니다. 인터넷·외부 서버·실제 상대 기기로 전송하지 않습니다.
- 데이터 인터랙션은 메시지를 생성하지 않습니다. ‘대화’ 탭은 별도로 양쪽에서 주고받을 수 있습니다.
- 체험 상태는 localStorage `sai-pair-v1`에 저장합니다. 기존 목업의 `sai-demo`와 분리됩니다.
- 브라우저가 로컬 저장을 막아도 같은 실행 중의 인터랙션은 계속 작동합니다. 새로고침 후에는 유지되지 않을 수 있습니다.
- 새로 열었을 때 진행 중이던 호흡과 데이트 기록은 취소 상태로 바꾸어 부재 중 완료나 시간 누적을 막습니다.
- 심박으로 거짓말·감정·관계 점수를 판정하지 않습니다. 혈관 진단이나 혈압 측정을 약속하지 않습니다.

## 소스와 빌드

최신 두 화면 목업:

- `pair-model.js`: 두 사람의 상태·공유·참여·합의·활동 완료 규칙
- `pair-app.js`: 각 휴대폰의 한국어/일본어 UI
- `pair.css`: 휴대폰 내부 스타일
- `pair-host.js`: 두 화면 연결, 로컬 저장, 공통 시연 메뉴
- `pair-host.css`: 두 휴대폰 배치와 모바일 화면 전환
- `scripts/build_pair.py`: 위 소스를 단일 HTML로 생성

```sh
python3 scripts/build_pair.py
node scripts/test_pair.cjs
```

이전 한 화면 버전은 `app.js`와 `style.css`를 사용하며, `python3 scripts/build_mobile.py`로 `mobile-single.html`을 생성합니다. 이 명령은 최신 `mobile.html`을 덮어쓰지 않습니다.

## 검증

- 모든 JavaScript 문법 검사 통과
- 상태 규칙: 참여 동의, 본인·상대 행동 구분, 날짜별 합의·취소, 돌봄 수락·완료, 심박 수신, 호흡 타이밍·중단, 각자 걷기, 시간 겹치기, 추억 저장, 보상 중복 방지 확인
- 두 개의 독립 UI 실행 컨텍스트에서 한국어/일본어 화면 생성 및 실제 이벤트 핸들러의 반영 확인
